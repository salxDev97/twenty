# ONE-110 — права на запись: ядро и модуль onema-access

Ветка `onema/one-110-rls-core` от `onema/v2.45.0`. Первый из четырёх PR
(ONE-110…113) по ADR-003. Основание — `docs/research/rls-design.md` §4, §5, §10
в репозитории `BPMN Onema`.

## Что сделано

**Точка встраивания №1.** Вызов `applyOnemaRowAccess` в конце
`applyRowLevelPermissionPredicates`
(`packages/twenty-server/src/engine/twenty-orm/repository/workspace-repository.ts`).
Через этот метод проходят все SELECT и COUNT ORM, а также критерии
UPDATE/DELETE/restore, значит одним вызовом закрыты GraphQL, REST, поиск и
Cmd+K, экспорт CSV, связи, join-и, группировки и агрегаты.

**Модуль** `packages/twenty-server/src/engine/onema-access/`:

| Файл | Что делает |
|---|---|
| `types/onema-access-rules.type.ts` | типы правил и результата |
| `utils/onema-access-rules.schema.ts` | zod-схема файла правил |
| `utils/parse-onema-access-rules.util.ts` | разбор + проверка ролей, циклов и глубины |
| `utils/load-onema-access-rules.util.ts` | чтение файла по `ONEMA_ACCESS_RULES_PATH`, кэш |
| `utils/resolve-onema-access-subject.util.ts` | участник (`$me`) и его роли |
| `utils/compile-onema-row-access.util.ts` | компилятор условий в SQL |
| `utils/apply-onema-row-access.util.ts` | навешивание условия на алиасы запроса |
| `README.md` | формат правил и умолчания |

Пример файла правил — `packages/twenty-server/onema/access-rules.example.json`,
переменная описана в `packages/twenty-server/.env.example`.

## Модель правил: что отличается от дизайна

Формат тот же, но имена ключей развёрнуты под правило форка «без сокращений»:
`backFk` → `backForeignKey`, `fk` → `foreignKey`. Реализованы `all`, `eq`
(`$me`, строка, число, булево, `null`), `exists`, `parent`, `and`, `or`.
`anyParent` и `linked` схема **отвергает** — они в ONE-112.

Умолчания (ADR-003, «закрыто по умолчанию»):

- объекта нет в правилах — работают только права Twenty на объект и поле;
- объект есть, роли участника нет — ноль строк;
- несколько ролей — условия через `OR`;
- `$me` неизвестен (API-ключ, приложение) — условие ложно;
- `parent` ложен при пустом внешнем ключе: сирота видна только ролям с `all`;
- системный контекст и `shouldBypassPermissionChecks` — правило не применяется;
- запрет — пустой результат (`1=0`), не ошибка прав.

Невалидный файл правил останавливает сервер и воркер: схема, необъявленная
роль, цикл `parent`, вложенность глубже трёх объектов.

## Тесты

**Юнит — 29 тестов, зелёные.**
`npx jest packages/twenty-server/src/engine/onema-access --config=packages/twenty-server/jest.config.mjs --rootDir=packages/twenty-server`

- компилятор: `all` → open; объект вне правил → open; роль не названа → denied;
  `eq` с `$me` на join-колонку связи; `$me` без участника → denied; обычное
  значение и `null`; `OR` по ролям участника; `exists` с вложенным условием;
  `parent` с условием родителя; `parent` при закрытом родителе → denied;
  `parent` при открытом родителе всё равно требует существования родителя;
  неизвестное поле и неизвестный объект → исключение;
- схема и проверка файла: валидный файл; незнакомое условие (`anyParent`);
  role id не uuid; роль без объявления; цикл; глубина > 3;
- загрузчик: переменная не задана → `undefined`; чтение и кэш; отсутствующий
  файл; не-JSON; разбор примера из репозитория;
- точка встраивания: без правил ничего не добавляется; условие на главный
  алиас; один раз на алиас при повторных вызовах; `1=0` на join-алиас закрытого
  объекта; системный контекст пропускается; API-ключ без `$me` → `1=0`.

Прогон соседних тестов ядра: `npx jest packages/twenty-server/src/engine/twenty-orm …`
— 603 теста, зелёные.

## Сборка образа

```bash
docker build \
  --target twenty \
  -f packages/twenty-docker/twenty/Dockerfile \
  --build-arg APP_VERSION=v2.45.0-onema.1 \
  -t onema/twenty:v2.45.0-onema.1 \
  .
```

Образ `twenty` = сервер + фронт, базовый `node:24.19.0-alpine3.23`. Правила
доступа кладутся в контейнер отдельно (том или слой поверх) и указываются
переменной `ONEMA_ACCESS_RULES_PATH`; без переменной образ ведёт себя как
апстрим.

**Собран: `onema/twenty:v2.45.0-onema.1`, 1.84 ГБ, локально (не публиковали).**
Проверено внутри образа: модуль `dist/engine/onema-access/` на месте, вызов
`applyOnemaRowAccess` есть в скомпилированном `workspace-repository.js`.
С базой данных образ не запускали.

**Грабли сборки.** На Docker с 8 ГБ памяти сборка одной командой падает:
BuildKit гонит стадии фронта и сервера параллельно, и `lingui:extract` то
роняет Node, то не дожидается воркера nx (`Did not receive an init message
from worker after 10000ms`). Лечится последовательной сборкой — сначала стадия
фронта, потом цель целиком (вторая берёт первую из кэша):

```bash
docker build --target twenty-front-build -f packages/twenty-docker/twenty/Dockerfile .
docker build --target twenty -f packages/twenty-docker/twenty/Dockerfile \
  --build-arg APP_VERSION=v2.45.0-onema.1 -t onema/twenty:v2.45.0-onema.1 .
```

Запасной путь, предусмотренный самим Dockerfile: собрать фронт на хосте
(`npx nx build twenty-front`) — стадия подхватит готовый
`packages/twenty-front/build/`.

## Открытые вопросы

1. Имена объектов и полей в `access-rules.example.json` — черновик из
   rls-design §5; окончательные придут из модели данных (ONE-5xx). Боевой файл
   правил создаётся отдельным PR с ревью двумя моделями (ADR-004 П-5).
2. Производительность не замерена: +1 WHERE на запрос и на join, `exists` и
   `parent` — подзапросы по индексу внешнего ключа. Замер — стенд ONE-002.
3. Кэш правил живёт до перезапуска процесса; перечитывание по сигналу не
   делали — правка правил идёт через PR и выкладку.
