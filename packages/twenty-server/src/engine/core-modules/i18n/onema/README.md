# Onema: полнота русского каталога (ONE-107)

Отдельный модуль форка `salxDev97/twenty`. Апстримный код он не трогает —
только читает каталоги `locales/*.po` и `locales/generated/*.ts` и падает,
если русский перевод где-то потерялся.

## Зачем

Требование владельца Onema от 2026-10-12: «абсолютно все тексты, анимации и
т. д. должны быть на русском». Половина строк интерфейса приходит из ядра
Twenty, то есть из этих каталогов. Пустой `msgstr` или перевод, совпадающий с
английским исходником, ядро молча показывает по-английски — поймать это можно
только сверкой каталога, что здесь и сделано.

## Что проверяется

1. **Нет пустых переводов.** Исключения — коды и псевдонимы, которые
   пользователь вводит латиницей (`ol`, `ul`, `p`, `ordered`, `CRUD`).
2. **Перевод не равен английскому исходнику.** Исключения — бренды
   (`Cursor`, `VS Code`, `Google`), коды (`JSON`, `OAuth`, `MCP`), примеры
   (`imap.example.com`, `sk-...`) и строки из одних подстановок.
3. **В подписях объектов и полей нет латиницы.** Это то, что владелец видит
   в каждой таблице и карточке: `msgctxt "objectMetadata.*"` и
   `msgctxt "fieldMetadata.label"`. Исключения — те же коды и бренды.
4. **Скомпилированный каталог согласован с `.po`.** Ядро читает не `.po`, а
   `locales/generated/<locale>.ts`; перевод, добавленный в `.po` без
   перекомпиляции, не виден в интерфейсе вовсе. Проверка ловит ровно это.

## Строки, которых нет в каталоге апстрима

Часть подписей стандартных объектов и полей собирается в коде без `msg`,
поэтому экстрактор lingui их не видит и в `en.po`/`ru-RU.po` их нет. Сервер
при этом ищет перевод по хешу самой строки
(`translateStandardLabel` → `generateMessageId`), так что достаточно добавить
запись в каталог — что и сделано (см. записи с пометкой
`#. ONE-107` в `ru-RU.po` и `en.po`). Если апстрим когда-нибудь обернёт эти
подписи в `msg`, `lingui extract` подхватит их сам, а наши записи совпадут с
новыми по ключу.
